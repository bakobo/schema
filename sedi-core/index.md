# SEDI Core Identity

The state issues Core to the citizen. Its individually disclosed blocks are given name, middle name, family name, name suffix, birth date, facial image proof, legal presence status, and issuance and expiration dates; a required boolean `primary` is true only on the management copy issued to the SEDI Management AID and false on bulk-issued copies. Its required `utahAgent` edge links the issuing department to an authorizing agent credential (its `d` and `u` are optional), and an optional `guardians` edge group, an m-ary operator over up to four guardian edges (`first` to `fourth`), links a ward's Core to the guardianship credentials that name the ward. This is [Sam Smith's Core schema at keripy `927c0cb8`](https://github.com/WebOfTrust/keripy/blob/927c0cb8/tests/sedi/test_sedi.py#L432-L804), the last planned re-pin before the Summit freeze, reproduced byte for byte with SAID `EN0JtdzBmFuTUzyJG9CXZhtdu-bW0V6L95bsVBzi-cY-`. [His `80f77b73` revision](../sedi-core-pre-927c0cb8-0.1.0/), which required `d` and `u` on `utahAgent` and misspelled presence in the `legalPresenceStatus` descriptions, and [his `9a8b7aa7` revision](../sedi-core-pre-guardians-0.1.0/), which lacked the group, remain resolvable. Sam Smith is the author. Each attribute block is either an expanded object or its compact SAID string, which is the partial-disclosure fix Bakobo's [0.2.0 amendment](../sedi-core-0.2.0/) anticipated. Sam's schema leaves the group's operator and each member's far schema and operator as free strings, and makes the group optional, so a verifier must hold the group to `AND` or `OR` and each member to the guardianship schema and `NI2I`, and a ward authorization's `authority` to a guardianship the subject Core's group names. The `utahAgent` edge has no compact arm, so an issuer or holder compacts the whole edge section or keeps the edge expanded. [Version 0.1.0](../sedi-core-0.1.0/) preserves Sam's earlier schema at `ec307cd74`. A verifier must resolve and verify compact references before using their claims.

**Legal presence status is endorsed.** Sam Smith confirmed in an email to Daniel Hardman on 2026-09-23 that `legalPresenceStatus` is an endorsed status, not only an input to proofing. The State plans visitor SEDIs, for example for Olympics visitors and out-of-state hunting licence holders, whose statuses are other than citizen. The values are still to be decided, so the schema keeps the field a free string. Utah Code [63A-20-301(2)(f)](https://le.utah.gov/xcode/Title63A/Chapter20/63A-20-S301.html) names name, birth date, image, and Utah residence address as endorsed attributes.

[`example.json`](example.json) is Guy's Core, [`examples/gal.json`](examples/gal.json) is Gal's and [`examples/wyn-ward.json`](examples/wyn-ward.json) is Wyn's, all from Sam's `test_sedi_acdcs` at `927c0cb8`, unmodified. Wyn's `guardians` group is `OR` over two edges by `NI2I`: `first` reaches Guy's guardianship ([`sedi-guardian/examples/guy.json`](../sedi-guardian/examples/guy.json)) and `second` reaches Gal's ([`sedi-guardian/example.json`](../sedi-guardian/example.json)). Each `utahAgent` edge carries Sam's `DI2I` operator and names his Agent schema as its far node; those are his data, kept verbatim, and the demo keeps its own stand-in agent schema. [`invalid/`](invalid/) holds negative cases. `this.i` `@3x2jtfxc`, `@hxqwde3o` and `@6uxg0vj0` record the re-pins.
